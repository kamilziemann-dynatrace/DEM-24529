Dynatrace Synthetic Flow

Recommended step-by-step setup for these three pages when you want a clean, repeatable Synthetic run and readable request ordering.

Recommendation: create three separate browser monitors, one per pattern. That gives you the clearest waterfall and avoids mixing unrelated requests in a single run.

1. Choose one scenario per monitor

Use a dedicated monitor target URL instead of the launcher page or folder index.

xhr-triggered-in-callback-of-xhr.html?autorun=1
xhr-triggered-in-load-phase-of-page-load.html
page-load-triggered-in-xhr-callback.html?autorun=1

2. Use the GitHub Pages project URL as base

For this repository, the expected project-site base path is:

https://kamilziemann-dynatrace.github.io/DEM-24529/xhr-lifecycle-patterns/

Append the selected scenario path directly after that base.

3. Keep the script simple

For the two autorun scenarios, a single open-page step is enough. Wait for page stability or the final target page, then stop. Do not add extra clicks unless you are intentionally testing manual interaction.

4. Interpret each pattern correctly

XHR triggered in callback of XHR: expect two same-origin XHR requests in sequence, where the second begins only after the first callback runs.

XHR triggered in load-phase of a page load: expect the request to appear during the initial load lifecycle of that page.

Page load triggered in XHR callback: expect one XHR first, then a real page navigation to next-page.html.

5. Use the right success condition

For the navigation scenario, assert the final URL contains next-page.html. For the other two, success is simply a 200 response from the expected fixture requests and a stable page state.

6. Know the GitHub Pages limitation

GitHub Pages is static hosting. You can validate order and correlation, but not controlled backend latency. If you need guaranteed 300-800 ms server delay, host the JSON endpoints on a small backend instead.

Practical monitor split:
Monitor A: sequential XHR chaining.
Monitor B: load-phase request on initial page lifecycle.
Monitor C: XHR followed by navigation to a new page.
